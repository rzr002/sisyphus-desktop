# Sisyphus：把桌面画面变成可攀爬地形

## 要实现的体验

小人只关心眼前有没有可以抓住的视觉结构。字的笔画、图片的轮廓、图表的线、彩色块之间的边界，都能构成落手点；均匀色块内部和缓慢渐变没有抓力。用户在文档里打出一行字，就相当于放了一块岩石；删掉小人正在抓的部分，岩石消失，小人掉落。

**桌面最终显示出来的像素，就是游戏的地图。** 不需要浏览器扩展、DOM、OCR、文档 API 或每个应用的适配器。前景窗口覆盖了后面的内容，最终画面自然反映遮挡。

“不光滑”是游戏规则中的视觉粗糙度，不代表现实材质的摩擦系数。这条规则应该稳定、直观、可调，而不是猜测画面的语义。

## 最终交互：桌面上只有一个小人

- 桌面常驻一个 96 × 112 pt 的透明角色窗口。蜘蛛侠有丝相连时，人物后方还会出现一层可穿透点击的蛛丝。
- 左键按住即可拖动，松手后受重力下落。暂停状态下拖动可以重新摆放，继续后恢复重力。
- 右键（或 Control + 单击）打开原生菜单：暂停/继续、重新出发、设置、退出。没有拿到屏幕帧时，增加读取状态、重新连接和权限入口。
- 鼠标停在角色上时暂停位移，给点击和拖动留出稳定目标；快速掠过仍可触发坠落。菜单关闭或拖动结束后有短暂保护，避免操作本身被当作干扰。
- 菜单打开、暂停和拖动时停止屏幕流；结束后读取新画面，避免用过期地形。
- 普通桌面区域没有输入遮罩。只有角色的小范围接收鼠标，不要求辅助功能或输入监控权限。

## 像素数据流

```mermaid
flowchart LR
  A[主显示器的最终画面] --> B[ScreenCaptureKit 连续采样]
  B --> C[RGB 相邻像素差]
  C --> D[可抓取像素场]
  D --> E[小块聚合成候选支点]
  E --> F[选择手臂够得到的下一处]
  F --> G[60 Hz 四肢和身体动画]
  D --> H[复查当前承重接触点]
  H -->|连续两帧没有抓力| I[松手与重力坠落]
  I --> J[落地起身与横向找路]
  J --> F
```

角色和鼠标指针从采样中排除，避免小人抓住自己或光标。生产应用只有真实桌面功能。自动验证使用的内部测试窗口由 DEBUG 编译条件隔离，不包含在发布的 .app 中。

## 1. 如何判断一个地方能不能抓

对像素 `p`，比较它和右、下相邻像素的 RGB 值：

```text
边缘强度 E(p) = max(
  |R(p)-R(p+右)|, |G(p)-G(p+右)|, |B(p)-B(p+右)|,
  |R(p)-R(p+下)|, |G(p)-G(p+下)|, |B(p)-B(p+下)|
)
```

超过阈值的像素有明显的颜色断点。保留 RGB 三个通道，是为了识别“亮度相近、颜色不同”的边界；仅转成灰度会漏掉这类结构。

然后分成小网格，统计每格中足够强的边缘数量。只有少量孤立噪点的格子被丢弃。相邻合格格子可合并为短支点，供规划器查找。**支点矩形用于找路；实际承重仍要回到局部像素检查。** 不能仅凭“这个矩形还在”就认定手里还有东西。

| 画面 | 结果 |
| --- | --- |
| 白底黑字、深色模式的亮字 | 字的轮廓可抓 |
| 彩色图形、大圆圈、曲线、图表 | 边界与线条可抓 |
| 大幅图片中的细节 | 有足够颜色断点的地方可抓 |
| 纯色矩形内部 | 无支点 |
| 纯色矩形边界 | 可以有支点，因为两侧颜色突变 |
| 缓慢渐变、很淡的水印 | 通常无支点 |
| 文字被删除、图片被擦掉 | 原接触位置失去抓力 |

这里故意不限制“只能是小字大小的连通区域”。否则大图形、大图标、长曲线会被错当作不可攀爬，而恰好违背应用无关的目标。

## 2. 为什么删除文字会让它掉下来

小人抓住一个支点时，记录的是**屏幕坐标中的承重位置**。每个新画面到来，都在这些位置周围一个小圆内重新统计边缘。

1. 当前接触附近仍有足够边缘：继续抓住。
2. 一帧看不到：暂时保留，容忍抗锯齿、压缩和采样抖动。
3. 连续两次采样复查都看不到：松手，进入坠落。

静态画面可能不持续发送完整新帧，因此还以 10 Hz 复查最近的有效像素场。这样“删完文字后不再动鼠标”也会掉落。屏幕流报错、空白或暂停时清除地形，不能无限沿用失效画面。

因此，删除文字不需要知道文档里发生了“删除”事件。只要那个位置的结构不见了，结果自然发生。别处打字不应该让它掉下去，所以不能拿整页图像变化、整行文字长度变化来替代局部承重检查。

窗口元数据只提供辅助：窗口明显移动、关闭或被遮住时可以更快作出反应。核心抓力判断仍来自画面。滚动、动画和视频中的变化同样进入这条链路。

## 3. 它怎么找路

- 地面：扫描够得着的最低支点。找不到时左右巡逻，保持在地面。
- 挂住：在手臂最大水平距离和最大上升距离内寻找更高支点。
- 换手：保持原承重点，伸向新支点，再移动重心。
- 上方无路：沿当前有抓力的区域横移，寻找新的机会。
- 支点消失、鼠标干扰：进入重力坠落，落地后短暂停顿，再开始。

候选支点可以按“距离近、能上升、抓力较强”排序。初版使用短距离贪心选择，不承诺找到全局最优路线；卡住时横移本身就是游戏的一部分。

当前身体动画是简化的运动状态机。进一步逼真的手脚约束、逆运动学和重心模拟可以独立迭代，不需要改变像素地形接口。

### 蜘蛛侠的蛛丝

普通角色继续使用原有的手臂可达范围。蜘蛛侠在够不到下一处支点时，可以向 390 pt 以内的真实边缘发丝，也能跨过同一高度的栏间留白。候选矩形只用于筛选，丝端选用其中离目标最近且能通过抓力检查的边缘，避开单个噪点。水平转移间的间隔给角色留下观察新位置的时间。

起手发丝约 0.20 秒；快速拉索根据距离用 0.34–0.72 秒靠近锚点。能垂下足够长的丝时，角色会转入重力和轻微阻尼驱动的摆荡。有且仅有一个合适支点时依然能左右折返，约七秒后收丝回到支点。

摆速足够时，只在前进方向、手腕上方的可达边缘寻找下一个支点；条件相近时优先另一扇窗口。交替换手时旧丝继续承重，另一手用约 0.19 秒张开新丝。接住时从正在移动的手腕计算真实丝长与摆角，保留切向速度，随后逐渐收短。空中有足够余量时，下一次换锚可以提前松丝：身体沿抛物线前移，收膝翻身、伸手、接丝。低处的长丝会预看约 0.17 秒的摆角，按实际手腕位置缩短有效绳长，给身体基准点预留 18 pt 的离地距离。腾空前检查抛物线两端至少还有 44 pt 的净空；实际推进使用同一条轨迹，并把越过接丝时刻的帧截到该时刻。窗口边缘和地面附近会跳过翻身。新支点消失时，仍握住旧丝就继续摆荡，已经腾空则会落下。

动作参考：[Insomniac 谈如何在换锚时保持速度](https://blog.playstation.com/archive/2018/09/06/insomniac-interview-the-tech-behind-marvels-spider-man/)、[PlayStation 实机介绍中的 Web Zip](https://blog.playstation.com/2018/06/15/playing-marvels-spider-man-made-me-feel-like-spider-man/) 和 [Insomniac 的空中特技说明](https://support.insomniac.games/hc/en-us/articles/46730041467027-What-Accessibility-options-does-Marvel-s-Spider-Man-2-feature)。左右手和翻身的触发条件按桌面的尺寸重新设计。

固定期间重复检查丝端附近 5 pt 内的颜色断点。连续两次失去抓力、承载它的窗口移动或关闭，都会断丝。角色保留当时的速度并受重力下落。拎起和切换角色会清理蛛丝；暂停会同时冻结人物和蛛丝。

同一个透明窗体覆盖当前一至两根丝；翻身未出丝时隐藏，蛛丝图层忽略鼠标事件。采集画面时排除游戏自己的应用窗口，人物和丝都不会提供新的承重像素。[运动状态机](../Sources/ClimbCore/ClimbEngine.swift) · [摆荡模型](../Sources/ClimbCore/WebMotion.swift) · [蛛丝图层](../Sources/Sisyphus/WebPanel.swift)

### 两根丝如何把人弹出去

当摆荡把身体送到两个可达边缘之间，承重手保留旧丝，另一手射向对侧。第二根丝挂稳后，身体沿着来速减速、屈膝向下拉长两根丝，在最低点短暂停住。两根丝一起收紧，加速段末端的速度就是离丝时的速度。接下来的 0.48 秒走重力抛物线，最后 0.19 秒伸手把丝射回前方的真实落点。

出招前检查后拉点、出手点、抛物线顶点和接丝点的净空。每根丝单独核对像素和所属窗口。蓄力期间消失一端，另一端按手腕当时的位置接住身体。已经离丝时，如果预定的接丝点也消失，角色会坠落。[双丝轨迹](../Sources/ClimbCore/WebSlingshot.swift)

高速摆荡中的剪式踢沿用同一条摆线，握丝的手固定，腿借势踢出后收回。单点摆荡进入慢速段时，角色可以旋转半圈，放长蛛丝、悬停，再收回原处翻正。绘制倒挂时对握丝手使用身体旋转的逆变换，保证蛛丝端点始终贴着手套。

## 4. 更新频率与性能

画面理解与身体动画分开运行：

| 工作 | 本轮实现目标 | 原因 |
| --- | --- | --- |
| 屏幕内容采样与抓力场 | 10 Hz，按内容帧到达处理 | 删除支点后及时响应 |
| 承重接触复查 | 每个新像素场，静止时仍以 10 Hz 复查 | 删除后的静态画面也能释放抓握 |
| 窗口辅助检查 | 10 Hz | 快速发现移动/关闭 |
| 身体动画、鼠标碰撞、重力 | 60 Hz | 动作连续 |

10 Hz 加连续两帧判定意味着，**仅按采样计算的消失检测窗口约为 100–200 ms**；实际延迟还要加上系统采集、排队和处理耗时。这是设计预算，不是未经测量的端到端承诺。

像素分析放在串行后台队列；主线程只接收地形结果和驱动动画。限制采样尺寸和缓冲深度，不积累过时画面。暂停、拖动、打开菜单和退出时停止屏幕流。

启动时用 `CGPreflightScreenCaptureAccess` 检查已有授权。检查通过才连接 ScreenCaptureKit，收到首帧才开始移动。右键首次启用时调用系统授权 API，后续直接打开录屏权限设置。应用在连接前记下这次尝试，首帧成功后清除记录。若连接失败、用户在控制中心停止共享，或系统在首帧之前重启进程，应用会等待用户手动重连。打开权限设置后返回或按系统提示重开，可以使用新授权。短时空白画面只清空地形，继续等待同一条屏幕流。`Info.plist` 注册为普通 App 以便启动台收录，运行时设置 `.accessory` 隐藏 Dock 图标。

如后续实测耗电偏高，可增加角色周围高频、远处低频的分区更新，或用 Metal/Accelerate 处理边缘。这些属于后续优化，不是当前 demo 的已验证能力。

## 5. 桌面适配边界

这条方案兼容的是“能被系统正常捕获的可见画面”，与应用后端无关。文档、浏览器、终端、绘图软件和视频都走同一条像素管线。

- 系统屏幕录制权限必须由用户授权。
- 系统保护内容若返回空白，游戏就把它当成光滑区域，不绕过保护。
- 当前 demo 活动范围为主显示器；坐标换算和显示器变化已处理，跨显示器行走是另一个功能。
- 画面变化很快时，小人更容易掉落，这是动态地形的自然结果。可在后续加入抓力宽容度。
- 过密纹理可能让照片显得“到处都能爬”。这是玩法参数问题，可通过边缘阈值、网格密度、最大跨距调节。

## 验证方法

自动检查包括：纯色、平滑渐变、等亮度异色边界、大图形轮廓、局部擦除、坐标翻转、连续两帧丢失及非连续噪声。也可以将自己的两张示例截图传给核心检查程序。

原生验收包括：内部测试文档的文字删除、窗口移动与关闭、角色尺寸的输入范围、右键入口，以及 ScreenCaptureKit 实际回传画面。测试文件不会成为产品功能。具体通过项与未验证项记在 [VERIFICATION.md](VERIFICATION.md)，不把单元测试当成真实桌面已经验证。

API 依据：[ScreenCaptureKit](https://developer.apple.com/documentation/screencapturekit)、[SCStreamOutput](https://developer.apple.com/documentation/screencapturekit/scstreamoutput)、[采样间隔](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/minimumframeinterval)、[帧状态](https://developer.apple.com/documentation/screencapturekit/scframestatus)。
